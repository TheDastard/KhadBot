# KhadBot decisions log

Each row is a decision still in force and the reason for it. How the result works lives in the reference docs:
`docs/encounter/`, `docs/hosting/`, `docs/wcl/`, `docs/game-art.md`, the API contract (`contracts/openapi.json`)
and `.claude/rules/`. `.claude/rules/docs.md` says how to add or change a row.

Sources: the [Encounter Review Refactor plan](https://claude.ai/artifact/Q45H17JuH5EXK8oz17CzQE), the
[hosted architecture](https://claude.ai/artifact/PGYBvboaxK93jt6fo6eU3B) and its
[work plan](https://claude.ai/artifact/KaomaNz2SSroTk45DSy9zv), the
[dashboard design canvas](https://claude.ai/artifact/GJLAo3qYdKq24Ro79bN7cr) and the
[dashboard work plan](https://claude.ai/artifact/9Ns4vbDzBAjpq3Fy96LVC7). IDs missing from the table (D37 to D50)
are recorded in the hosted work plan's section 2.

| D34 | S3-compatible blob store | `KHADBOT_STORAGE=s3` stores blobs in a bucket, with `raw/` zstd-compressed; credentials are boto3's own | One code path for R2 and the local SeaweedFS; raw pages are the bulk and compress well | 2026-10-20 |
| D35 | Job functions | Ingest, process and review run as job functions over a Pydantic spec that holds IDs, never tokens; the CLI runs the same jobs | The queue needs serializable units it can retry, and the CLI running the worker's code keeps local mode from drifting | 2026-10-20 |
| D36 | Read-model tables | Hosted mode projects small per-pull rows into Postgres; the views aggregate in Python over rows from either source | The views must give the same numbers from Postgres as from records; aggregating in SQL could drift on ordering and float sums | 2026-10-20 |
| D51 | Python layers | Each package imports only those below it (import-linter, no exceptions); `wiring.py` is the one composition root | Layer cycles were deepening with every package, and one root means local and hosted can't drift | 2026-10-24 |
